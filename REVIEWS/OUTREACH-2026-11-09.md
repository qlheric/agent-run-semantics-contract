## 二、英文版（发 GitHub / Reddit r/LocalLLaMA / HN / A2A discussions）

> **Looking for 2 independent reviewers: a checkable contract for agent runs (v0.5.0).**
>
> Long-running agent systems fail in a specific way: not crash, but *ambiguity* — nobody can say whether the side effect happened. This repo turns that into a checkable contract: state machine + legal transitions, idempotency scope, integer micro-USD budget with `reserve → settle`, JCS-hashed audit chain that **replays** into the state sequence, and MCP `ToolAnnotations`-mapped capability tiers. Two independent implementations (Java control plane, Python translation layer) must emit **byte-identical** output; the Java-generated golden files are committed, so `python tools/check_golden.py` reproduces 35 byte-exact cases in CI.
>
> I'm not asking for stars. I'm asking one person who has actually built an agent control plane to spend 10 minutes on the questions that decide safety: Is any legal edge missing or unsafe in `contract/status-transitions.json`? Can `outcome_unknown` be re-entered? Can a retry double-charge under the `reserve → settle` wording? Open an issue or reply here: https://github.com/qlheric/agent-run-semantics-contract/issues/1

## 三、10 分钟审阅清单（对方只要回这 5 条）

1. `contract/status-transitions.json`：有没有**缺的合法边**，或**危险的合法边**？
2. `outcome_unknown → succeeded/failed` 要求 `evidence_ref`：够不够？能不能被伪造？
3. 预算 `reserve → settle`：并发重试下会不会**重复扣/漏扣**？价格快照粒度够吗？
4. 审计链：JCS 数组哈希的字段顺序/边界值合适吗？`--replay` 的 5 条判据有没有漏？
5. 工具注解折叠 MCP `ToolAnnotations`：`openWorldHint` 作为 `outcome_unknown` 预测变量，站得住吗？
