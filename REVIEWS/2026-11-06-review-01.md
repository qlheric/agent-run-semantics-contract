## 1. 我们复验的证据（可复跑）

### 1.1 硬伤 1 成立：权威转移表从未被校验器读取

```text
$ grep -n "status-transitions" tools/contract_check.py   # 只出现在注释与 x-status-transitions 逻辑里
→ 校验器只校验"文档根 x-status-transitions 的 key/value 在状态枚举内"，**不读取** contract/status-transitions.json
```

fixtures 内嵌表与权威表对照（我们实测）：

| fixture | 内嵌 `running` 目标 |
|---|---|
| `run_created.json` | `["succeeded","failed"]` |
| `run_failed.json` | `["failed","cancelled"]` |
| `step_full.json` | 7 个目标（与权威表一致） |
| **authority** | `["waiting_approval","paused","degraded","succeeded","failed","cancelled","outcome_unknown"]` |

**结论：成立。** 9 份 fixture 各带一份互不一致的表，而权威表无人读取。

### 1.2 硬伤 1 的安全洞成立：`outcome_unknown → running`

```json
"outcome_unknown": ["running", "failed"]
```

README §2.1 要求"恢复前先查幂等存储再决定是否重放"，但状态机允许 **unknown 直接回 running**（=未经对账就重新执行）。与 Once 论文（DOI 10.5281/zenodo.22969881）的 UNKNOWN 保守模型冲突。**成立。**

### 1.3 硬伤 2 成立：审计 hash 是手编的、公式对不上

```
entry0 stored hash : 3f2b1c9d8e7a6b5c4d3e2f1a0b9c8d7e6f5a4b3c2d1e0f9a8b7c6d5e4f3a2b1c0
entry0 formula(|)  : e64d095322a9da3646a406986bd8e0b2ec687aa9a0c96a1dc3586778a9ef2823
match: False
```
存储值本身就是**顺序递增的十六进制**（`3f2b1c9d 8e7a6b5c 4d3e2f1a …`），明显是手写占位符。**成立。**
另：`hash` 仅 `minLength:1`、`prev_hash` 无约束、`ts` 无格式约束——链不可校验。**成立。**

### 1.4 硬伤 3 成立：公开仓无法验证"两实现逐字节对拍"

```text
$ *.java files in repo: 0
$ .github/workflows/conformance.yml → 只跑 python tools/contract_check.py（无 Java、无 diff）
$ CONFORMANCE.md §3.1 让跑 python java/control-plane/contract_check.py → 仓中不存在该路径
```
**成立。** 这句话目前只是自述。

## 3. v0.3 动作清单（按评审建议 + 我们的取舍）

**第一批（不改变词汇、可独立验收）**
1. 校验器**读取 `status-transitions.json`** 作为唯一权威；fixtures 内嵌表必须与之相等，否则判红；
2. 新增 `--verify-chain`：按新公式复算 `run.audit[]`，并加一条"hash 不匹配 ⇒ 必须被拒"的 negative fixture；
3. 审计链哈希改为 **JCS(JSON 数组 8 分量) → sha256**，重算全部 fixture hash；`hash`/`prev_hash` 加 `^[0-9a-f]{64}$`；`ts` 加 RFC 3339 UTC 毫秒格式；
4. 修 `side_effect_unknown`（入 schema 或从 README 删）、`x-status-transitions` 取消 required、`args_schema.type` 去掉 `number`；
5. 发布 **golden 期望输出**（Java 生成）并让 CI 做 diff，使"双实现一致"可外证。

**第二批（破坏性词汇/结构变更，待 A2A 讨论与评审确认后落）**
6. `waiting_approval` → `input_required`；`outcome_unknown` 保留 + 新增 `outcome_confirmed/outcome_absent`，删除 `outcome_unknown → running`；
7. `degraded` 拆到 `run.mode`；`*_usd` → `*_micro_usd`；
8. 工具分档标注映射自 MCP ToolAnnotations；幂等键标注映射 IETF draft；
9. 发布为 **A2A Extension**（URI + params schema）+ 独立 conformance 套件。

### 5.2 我们**推翻**了初版记录里的一条处置

| 评审意见 | 初版处置 | **更正后** |
|---|---|---|
| `waiting_approval` → `input_required` | 接受改名 | **拒绝改名**。评审原文说得很清楚：`input_required` 是"缺数据，请补给我"，审批闸门是"缺授权，请批准一次副作用"——前者数据依赖，后者策略判定；合并等于把"人批准副作用"退化成"模型等参数"，正好摧毁我们自己主张的"闸门在模型外"。A2A 同时保留 `INPUT_REQUIRED` 与 `AUTH_REQUIRED` 正是拒绝合并。正确做法：**保留 `waiting_approval`**，在附录声明协议层映射到 A2A `INPUT_REQUIRED`，区别由本 extension 承载 |

### 5.3 处置口径（更正后）

- **schema 独立、语义从属、传输寄生**：独立 normative schema（`$id` 换成可解析 URI、版本用版本集合而非 `const`），注册为 **A2A extension**（`AgentExtension{uri, required:false, params}`），MCP 侧只做字段映射、不改其状态机。
- **三件必做（评审 §7）**：①把 `reserve → settle` 写进 schema（或从 README 删掉这个卖点）；②canonicalization 换 **RFC 8785 JCS** + `ts_ms` 整数（收 JCS 附录 B 向量）；③`audit` 记录 `state_transition` + `--replay` 校验。
- **紧接着**：删掉 `capability_tier` + `side_effect`，改用 MCP 四个 hint（**保留 `openWorldHint`**，它是 `outcome_unknown` 的预测变量）；幂等概念从 4 个收敛为 2 个（`idempotency_key` + `dedupe_scope`）。
- **措辞**：novelty 从"语义"移到"**工件 + 一条不变量**"；"18 required fields" 改由校验器导出；测试数量后紧跟负向对照数量；"auditable" 改为"tamper-evident（本地）"，签名 checkpoint 列为后续。
